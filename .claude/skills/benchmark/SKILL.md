# /benchmark <URL> — 영상 해부

## 시작 전 (필수)

`studio/코어.md`와 대상 채널의 `채널.md`를 읽는다. `studio/벤치마크/해부/`에 같은 영상의 기존 해부가 있으면 중복 생성하지 않고 갱신한다.

## 절차

1. **유튜브 URL**: `video_analysis_create(youtube_url)` → 30~60초 간격으로 `video_analysis_status` 폴링(완료까지 3~5분, 백그라운드 sleep 활용). 쇼츠 길이일수록 정확 — 긴 영상이면 정확도 저하를 리포트에 명시.
2. **틱톡/릴스 URL** (video_analysis 미지원): WebFetch로 메타(제목/조회수/캡션)만 수집하고, 해부 표는 "수동 시청 필요" 틀로 남긴다.
3. **메타 보강**: WebFetch/WebSearch로 조회수·채널 정보 확인.
4. **리포트 작성**: `studio/벤치마크/_템플릿_영상해부.md` 구조로 `studio/벤치마크/해부/YYYY-MM-DD_{슬러그}.md` 생성. 핵심은 ① 훅 구조 ② 리텐션 장치 ③ 우리 채널 적용점(구체 구성안 1개).
5. **CSV 행 추가**: `studio/벤치마크/채널벤치마크.csv`에 1행 append.
5-1. **출처대장 자동 등록**: `studio/출처/출처대장.csv`에 유형=억대뷰쇼츠(또는 해당 유형)로 S### 연번 append — 해부된 영상은 곧바로 대본 근거로 인용 가능해진다.
5-2. **타임코드 역할 구분**: video_analysis 실측은 초 단위다. 0.1초 정밀도는 제작 스토리보드(/new-episode)에서 프리스크립티브로 설계하는 것 — 해부 리포트에는 실측 단위를 그대로 쓰고 억지 정밀도를 만들지 않는다.
6. URL이 여러 개면 해부를 haiku 서브에이전트들에 병렬 위임한다.

## 금지

크레딧 소모 도구(virality_predictor 포함 — 미디어 업로드+과금 가능), 발행, 삭제. 필요 시 "승인 필요" 출력만.

## 종료

mirOps 폴백 기록 + 보고(결론→바뀐 것→미르가 할 것) + 검수 3줄.
